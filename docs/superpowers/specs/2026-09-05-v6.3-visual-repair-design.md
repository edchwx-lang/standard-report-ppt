## 2. 不可越过的边界

1. 只修改正式蓝图锁定后、`construction_mode: deconstruct` 的路径。
2. 内容解析、事实依据、蓝图提示词、ImageGen 调用、生成次数、运输记录、正式蓝图字节与锁定门禁不变。
3. 位图模式、旧版兼容分支、交付包格式不变。共享文件只允许修改 V6.3 后锁定分支。
4. 母版文件及五个原占位符不变：章节、标题、核心判断、来源、页码只填文字，不能重建或调整字体、字号、位置、段落、边框。
5. 主体蓝图是视觉最高权威；禁止概念化改画、固定矩阵替换、统一调色及以“含义相近”为由替换图标。
6. 文字、数字、表格、图表、基础几何保持可编辑；复杂地图底图、照片、Logo、插画、复杂图标允许局部栅格素材，Logo 固有字样除外不得保留应编辑的正文/标注。
7. Windows 沿用 COM；Mac 沿用 python-pptx/OOXML，只同步共享规则和可实现适配，不声称完成 Mac 原生视觉验证。
8. Inline Execution；不采用逐阶段独立子 Agent 实施和复核。
9. 每个验证工程最多两次实际构建、最多一次定向视觉修订；运行故障与视觉差异分开记录，但不新增第三次构建额度。
10. 本方案和后续验证均不上传、不全局安装、不覆盖历史样本。推广发布另行确认。

## 4. 修复后的最短流程

`锁定核验 → 全图查看及源主体定位 → 重叠切片与逐对象普查 → 原生/素材分层 → 一次汇总预检 → COM 构建和渲染 → 一次对象级视觉比较 → 必要时一次定向修订 → 交付或明确结束失败`

这是现有步骤内部的调整，不增加常规用户确认门禁。所有发现汇总后一次处理，不为每个对象单独启动检查循环。

### 4.1 源主体定位与统一坐标

- 新增后锁定文件 `.build/v63_source_body_rois.json`：每页原图 SHA-256、图像尺寸、`source_body_roi_px`、查看依据。
- ROI 使用 `[left, top, width, height]`；对象/裁剪框沿用 `[x1, y1, x2, y2]`。字段不可混用。
- 先查看完整蓝图，排除上三层、来源、页码后确定主体。母版几何只定义输出容器，不再冒充源主体坐标。
- 切片保留 `FULL` 主体图和 `B01–B06`；增加 `PAGE` 全图引用供核查边缘。查看源图不是重新生成源图。
- 修复后的场景页声明 `coordinate_mode: source_pixels_contain`。源图坐标原样进入场景，不预先拉伸到母版坐标。
- 目标采用一个共享的等比例 contain 变换：`s=min(target_w/source_w,target_h/source_h)`，中心平移；所有路径点、对象框、图片位置与审计使用同一个变换。
- 地图与标签必须共享变换，不允许只缩放地图。图片保持宽高比，容器余白不通过拉伸图片填满。
- 本次验证重新普查三张原图，不能直接把旧场景里已经变换过的坐标当原始像素使用。

### 4.2 逐对象普查，防止再次重新设计

- 在候选上增加 `observed_subject`（如 `world_map`、`brand_logo`、`factory_icon`）、必要的 `parent_candidate_id` 和 `child_candidate_ids`。
- 父级只表示组织关系；每个独立的品牌、图标、标签、图表组成对象仍需自己的候选和去向。原子化不等于拆每个汉字或每个像素。
- 身份与实现类型不能相互覆盖：`world_map` 不能通过填 `basic_geometry` 获得几块多边形的替代许可。
- Logo 默认逐个裁剪；复杂图标默认逐个裁剪。确属少量基础几何、且可忠实还原的图标可原生重建，但不能用通用符号替代。
- 图表须登记轴、刻度、单位、序列、数据标注和图例；面板存在不等于内容完整。
- 在现有切片查看中核对分类清单（地图、Logo、图标、照片、图表细节），不再新增一轮全量重复普查。
- 普查输出包含编号叠加预览，便于一次发现“图上有但清单没写”的对象；编号图仅诊断，不作正式素材。

### 4.3 局部素材分离

保留 `image_crop` 原子，仅扩展提取配方，避免更换场景图或渲染器体系。

配方分三级，依序选最简单可行的一种：

1. `rect_crop`：清洁 Logo、照片、图标直接紧边界裁剪。
2. `masked_crop`：对不规则底图/图标使用局部多边形蒙版；标注、图例、线条等单独扣除并绑定对应原生对象。
3. `local_cleanup`：仅在确认背景单一的派生素材局部，用采样纯色填补；不生成新地理轮廓、品牌细节或事实信息。

不得调用 ImageGen 重新画蓝图，也不新增地图数据下载、自动国界矢量化、通用 OCR/分割服务或大型视觉依赖。

地图的特殊约束：

- 一张复杂地理底图可作为一个连贯视觉主体，不要求每个国家拆成图片。
- 地名、数值、图例、定位点、线条、说明框全部原生化，位图中对应旧像素必须去除；禁止叠一层可编辑字就声称合格。
- 原标注遮挡的未知底图不臆造。若移除后形成空洞，可由同位置的不透明原生标注覆盖，但必须记录该底图缺乏被遮挡区域信息；移动标注不保证显露完整地图。
- 对暴露在可见区域的底图空洞、残字、重影必须在视觉报告中显式记录；严重到地图失真则样本不通过，不无限修图。
- 去除区域与原生叠加物之间要有绑定关系；不是任意涂白一块区域。

每个资产记录 `asset_id`、源图哈希、源框、蒙版/清理配方及哈希、输出哈希、观察主体、绑定场景对象和插入次数。原图字节永远不动。任意外部路径逃逸或配方篡改都拒绝。

TEST 第 1 页右下角特别检查：地图、装饰柱形/箭头、手机、平台 Logo 不能合为一个“插画”截图来绕过编辑性。可辨识的非 Logo 文字按文字处理；无法辨识部分记为不确定，不编造、不假报完整。

### 4.4 Windows 原子渲染小修

- 点集是路径几何的唯一来源；规范化时推导框。水平/竖直线允许零高/零宽；零长度线、NaN、越界点仍拒绝。
- 新增 `closed` 路径属性，默认保持已有闭合行为；开放折线不再自动闭合。曲线可用足够密的原生节点近似，不再用首尾两点替代弯曲结构。
- 图表区域填充和边线可分别建原生形状，保留刻度、单位、可编辑数据标注及红色强调。不在本次引入完整渐变/贝塞尔编辑器；残余渐变差异如实报告。
- 富文本先用真实 COM 小样复现，再在正文 `_render_text` 内修正字符范围调用，保留 runs 的颜色、字号、加粗与换行。不能降低为单色，也不改母版更新器。
- 实现以单个文本框保留 runs 为首选；如需多个文本框回退，必须有准确的逐 run 位置及一对多审计，不在本次未经验证直接采用此回退。
- 保存及渲染沿用现有后端，不借本次修复重构整个 COM 生命周期。已存在的两次打开行为如非故障根因，不列为必修项。

### 4.5 验收、修订和停止

三类结果分别表示，不能混为“通过”：

| 维度 | 证明内容 | 不能代替什么 |
| --- | --- | --- |
| 结构有效 | PPT 可打开、原生对象/资产/占位符可验证 | 不能代替视觉保真 |
| 视觉合格 | 对照原图主体，内容、独立对象和布局无重大缺失 | 不能只看低频相似度 |
| 带警告可交付 | 结构有效，剩余差异明确披露并已停止重构 | 不等于修复版本验证成功 |

- 汇总预检一次包含覆盖、提取、坐标、运行支持和 hash 问题，避免尾端才暴露可确定的几何问题。
- 渲染后同一 Agent 看三张主体和重点局部，写 `.build/v63_visual_review.json`；绑定 PPTX、渲染图、蓝图、普查和场景哈希，记录具体对象及差异，不能只填 `passed: true`。
- 现有低频评分保留诊断作用。分数通过不能覆盖漏 Logo、错地图、内容缺失或图标替换。
- 未写视觉复核记录时进入 `awaiting_visual_review`：已有 PPT 与渲染保留，不重构，不写合格凭证。同一任务完成复核后恢复终结步骤，不创建用户确认关卡。
- `targeted_refinement` 必须 `accepted=false`；`block` 也不能写合格缓存；只有 `deliver`、`deliver_with_warnings` 且结构有效、复核已绑定时可锁定。
- 已接受输出以完整输入合同和 PPTX 哈希复用，不再打开 PowerPoint；过时的场景、裁剪配方或审查记录使接受凭证失效，不能悄悄复用旧结果。
- 初次普查快照保留。一次修订允许有图像依据的补录/细化：添加漏 Logo、拆分粗候选、纠正观察类型。不能删掉应保留对象来让审计通过；被细化父项必须有后继子项的完整覆盖。
- 补录/更正记录原候选、原因、源像素框和新增绑定；蓝图、母版及事实来源仍硬锁。不能直接删除 census 的冻结保护而不加替代校验。
- 记录 `build_attempt_count`、`visual_refinement_count`、失败阶段和耗时。预检未打开 COM 不算构建，但同一未解决错误不盲目重试。
- 总构建上限仍为 2。首次运行故障后可使用剩余的一次恢复；恢复后即使有视觉差异也不增加第三次构建。正常首次出图后最多一次视觉修订。
- 第二次结构有效但仍有普通视觉差异：交付带警告 PPT；关键内容缺失、禁止的正文栅格化、损坏或无有效渲染：结束为失败，提供可用的诊断产物，不反复卡在流程。

### 4.6 Mac 最小同步

- 使用同一对象清单、源坐标变换、蒙版派生资产、路径开闭定义和编辑性规则。
- 共用的 JSON style 中字号、线宽和文本边距统一以 pt 表达；Mac 显式边距不得误当 inch。
- 支持透明 PNG、按比例放置及已有 OOXML 可表达的原生对象；不能表达的明确报错，不静默全图栅格化。
- 只运行 Python 构建、OOXML、资产/文本完整性、几何和母版合同测试；记录实际运行平台。
- 最终始终标记 `mac_native_render_unverified`，不以 Windows 截图替代 Mac 视觉证据。
