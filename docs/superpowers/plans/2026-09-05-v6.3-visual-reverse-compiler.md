# V6.3 Visual Reverse Compiler Implementation Plan

> **For Codex:** Use `superpowers:executing-plans` to implement this plan
> task-by-task with inline execution and verification. Do not use independent
> per-stage sub-agents.

**Goal:** Upgrade only the post-lock deconstruction path so Windows reconstructs
locked blueprint bodies with S3-pilot-level visual fidelity and editability,
while macOS consumes the same scene graph on a best-effort basis.

**Architecture:** Add a hash-bound independent visual census and atomic scene
graph between blueprint lock and compilation. Preserve the five template
placeholders and render only the blueprint-owned body through new platform
adapters. Keep every pre-lock and bitmap path frozen.

**Technology:** Python 3, Pillow, PowerPoint COM/win32com on Windows,
python-pptx/OOXML on macOS, unittest, existing PowerPoint render/audit pipeline.

**Branch:** `codex/v6.3-visual-reverse-compiler` from
`d3c9103841e59e50de801a472055b49758ddb4a6`.

**Design reference:**
`docs/superpowers/specs/2026-09-05-v6.3-visual-reverse-compiler-design.md`.

## Execution rules

- Work inline in this branch; implement and verify tasks sequentially.
- Do not merge or cherry-pick the old `codex/v6.3-deconstruction-runtime`
  candidate.
- Do not install globally, push, or tag until the final S3 review is accepted.
- Use test-first changes for each production behavior.

- No task may alter ImageGen behavior, formal blueprint bytes, or bitmap code.
